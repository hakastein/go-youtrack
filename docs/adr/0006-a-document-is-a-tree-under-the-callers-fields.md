# Документ — дерево под выражением вызывающего, а отсутствующее имя проверяется по `$type`

Сервер присылает только поля из `fields=` и под `200` молча опускает и опечатку, и имя, которого нет у типа объекта.
Сгенерированные структуры не умеют отправить `null` и различить «не запрошено» и «пусто». Здесь решено, как модуль
строит документ ответа и когда отсутствующий ключ — ошибка. Факты измерены на YouTrack 2026.1.13757.

## Решение

- **Ответ и тело запроса — деревья.** Отсутствующий ключ в теле — третье состояние рядом с текстом и явным пустым
  значением, и такую часть сервер не меняет. От сгенерированного клиента остаётся поверхность операций, но не тела
  ([ADR-0004](0004-the-generator-owns-the-operation-surface.md)).
- **`fields=` выбирает вызывающий,** пустое выражение — поля по умолчанию операции, `+x` — они и `x`. Выражения
  «запросить всё» нет, потому что схема рекурсивна. Поля по умолчанию — только те, которые видит любой читатель.
- **Синтаксис проверяется до запроса, имена — после.** Одно неверное имя проваливает всю операцию: неполный документ
  потребитель принял бы за полный.
- **Отсутствующий ключ K проверяется по каталогу схем, по `$type` T, который сервер назвал у объекта:**

  | Случай | Результат |
  |---|---|
  | T из набора схем узла и объявляет K (сам или через предка) | `upstream_invalid` |
  | T из набора и не объявляет K, а другая схема набора объявляет | не ошибка, K опускается в узле этого объекта |
  | T не из набора (нет в каталоге, не назван, чужой узлу), а K объявлен в наборе | `upstream_invalid` |
  | K не объявляет ни одна схема набора | `unknown_name`; если имя запросил сам модуль — `upstream_invalid` |

  Имена проверяются после обхода всего ответа; при обоих кодах ошибка — `upstream_invalid`. Полученное поле, которого
  нет в спецификации, не ошибка. Набор схем узла — схема ответа операции с потомками в корне, ниже — схемы, которые
  набор выше объявляет у поля, а если он объявляет скаляр или объект без схемы, — все иерархии, названные сервером в
  этом узле. `unknown_name` несёт `request`, `fields` и `unknown: [{field, nearest}]`, `upstream_invalid` —
  `missing: [{field, type}]`; `nearest` — до пяти имён набора не дальше двух правок, а если таких нет — все имена набора.
- **Имена под `customFields` сверяются с каталогом кастом-полей инстанса,** потому что это не свойства схем, а токену
  без роли в проекте поля проекта приходят пустыми. Каталог читается один раз за вызов и только если вызывающий назвал
  хотя бы одно имя. Совпадение — как у сервера: без учёта регистра, по `name`, при пустом `name` — по
  `localizedName`; канонический `name` уходит в запрос и становится ключом.
- **Каталог схем генерируется** `scripts/catalogue.go` из `api/openapi.json` в `catalogue.gen.go` (`make generate`) и
  руками не правится; `make ytapi` сверяет его байт в байт. Там же помечены скаляры времени и многострочного текста.

## Документ

- **Ключи — дословно из `fields=`, в порядке запроса.** Имя из выражения против грамматики `CheckKey` — `bad_usage`.
  Ключ из данных (имя кастом-поля, фраза связи) — `DataPair`; два одинаковых ключа из данных в одном отображении —
  `upstream_invalid`.
- **Многострочный текст — только строковые свойства `description`, `text` и `content`,** и только в записи, взятой
  целиком: в записи списка он строка.
- **Время — момент ISO 8601 в UTC, длительность — период из минут без дней** (`PT1H30M`, `PT0M`), потому что `P1D`
  сервера — рабочий день инстанса. Подвыборка под длительностью — `bad_usage`.
- **Адрес инстанса в ответе разрешается от адреса клиента по RFC 3986:** `url` и `thumbnailURL` у вложений,
  `avatarUrl` у пользователя, `iconUrl` у проекта. Не абсолютный путь — `upstream_invalid` с `upstream_value`.
  `base64Content` файла не запрашивается: подписанный `url` отдаёт файл без токена.
- **Кастом-поля задачи модуль упорядочивает сам:** названные — в порядке называния, взятые целиком — по `ordinal`
  привязки, при равенстве — по номеру привязки. Значение печатается по ключу значения типа поля; названного поля,
  которого у задачи нет, в документе нет.
- **Связи — отображение фразы связи на задачи.** Пустые слоты опускаются, `null` среди слотов — `upstream_invalid`:
  пропущенный молча, он спрятал бы связь.
- **Комментарии задаются выбором `Comments`, а не полем.** Нулевой выбор убирает и ключ, и запрос; удалённый
  комментарий выбрасывается, порядок — по `created`.
- **Запись отвечает документом записанного,** потому что воркфлоу может поменять другое поле, и ответ сверяется с
  отправленным: расхождение — `upstream_invalid` с `mismatch`, `actual` — присланное дословно.

## Значения активностей

- **`added` и `removed` — всегда список:** `null` — `[]`, одиночное значение — список из одного. Скалярный элемент —
  скаляр, объект — дерево по запрошенным именам; под ними у любой активности один набор схем — иерархия
  `ActivityItem` и `BundleElement`. Имя вне набора — `unknown_name` до запроса.
- **`category` — идентификатор YouTrack, `field` — имя кастом-поля в проекте или непереведённая фраза связи.**
  Вложенное имя под ними — `bad_usage`. Переведённую метку связи модуль сводит к фразе по `/api/issueLinkTypes` без
  учёта регистра.
- **Без категорий уходят все, категории разрешаются без учёта регистра,** незнакомая — `unknown_name` до запроса:
  запрос без `categories` сервер отвергает `400`, а незнакомую молча отвечает пустым списком.

## Отвергнуто

- **Тела с тремя состояниями по всей спецификации.** `$type` и `value` остались бы нерешёнными.
- **Отсутствие ключа — всегда ошибка** и **отсутствующий ключ просто опускается.** Ложные ошибки на `value(name,login)`
  или опечатка без ошибки.
- **Набор схем из присланных типов.** Результат зависел бы от данных.
- **Подтипы в overlay или рукописный список имён.** Вторая копия спецификации.
