# Документ — дерево под выражением вызывающего, отсутствующее имя проверяется по `$type`

Под `200` сервер молча опускает и опечатку в `fields=`, и имя, которого нет у типа объекта: без проверки опечатка
выглядит как пустое поле. Сгенерированные модели не отличают «не запрошено» от «пусто». Поэтому ответ — дерево под
выражением вызывающего, а каждое отсутствующее имя сверяется со схемой, которую назвал сервер. Факты — YouTrack
2026.1.13757.

- Ответ и тело запроса — деревья, а не сгенерированные структуры: ключ, которого нет в теле, сервер не меняет.
- Выражение полей — `fields=` REST API как есть и обязательно у каждой операции с `Fields`: пустое — `bad_usage` до
  запроса. Своих полей по умолчанию у модуля нет: какие поля печатать, решает вызывающий. Операции без `Fields`
  (удаление, `Tags.Add`, `Tags.Remove`) и выбор `Comments` отвечают своей формой. Выражения «все поля» нет: схема
  рекурсивна.
- Синтаксис выражения проверяется до запроса, имена — по ответу. Одно неверное имя проваливает операцию.
- Ключ K, которого нет в объекте с `$type` T:

  | Случай | Результат |
  |---|---|
  | T из набора схем узла и объявляет K | `upstream_invalid` |
  | T из набора не объявляет K, а другая схема набора объявляет | K опускается |
  | T не из набора, а K объявлен в наборе | `upstream_invalid` |
  | K не объявляет ни одна схема набора | `unknown_name`; если имя спросил сам модуль — `upstream_invalid` |

  Если в ответе оба кода — `upstream_invalid`. Поле ответа, которого нет в спецификации, — не ошибка. Набор схем узла:
  в корне — схема ответа с потомками, ниже — схема, объявленная у поля, а у скаляра или объекта без схемы — иерархии,
  которые назвал сервер. `unknown` несёт `nearest` — до пяти имён набора не дальше двух правок, а если таких нет, все
  имена набора; `missing` несёт `{field, type}`.
- Каждое имя под `customFields` сверяется с каталогом полей инстанса, а не с полями проекта: у токена без роли в
  проекте поля проекта пусты. Совпадение ищется так же, как у сервера. Каталог читается, только если поле названо.
- Каталог кэшируется вместе с метаданными проекта (`WithMetadataCache`), и этот кэш тоже подтверждает и не
  отказывает. Имя, которое кэш не разрешает в одно поле, отправляет каталог перечитаться, а `unknown_name` даёт только
  каталог, который сервер только что прислал. Так поле, созданное после записи кэша, находится со второго чтения, а
  обычный вызов обходится без запроса каталога. Поле, удалённое или переименованное после записи кэша, кэш ещё
  подтверждает: под старым именем оно не печатается, пока каталог не перечитает промах по другому имени.
- Каталог схем — `catalogue.gen.go`, его генерирует `scripts/catalogue.go` из `api/openapi.json` с `api/overlay.yaml`.
- У бандла пользователей сервер присылает `values`, которых нет в спецификации: людей и группы бандла, каждый своего
  `$type`. Overlay объявляет `values` списком объектов без схемы, и имена под ним сверяются с иерархиями присланных
  типов. Поэтому `bundle(values(name,archived),aggregatedUsers(login))` читает бандл поля любого типа: у поля
  пользователей под `values` печатаются имена людей и групп, `archived` опускается.

## Документ

- Ключи документа — имена из `fields=` в порядке запроса; имя вне грамматики `CheckKey` — `bad_usage`. Ключ из данных
  (имя поля, фраза связи) — `DataPair`; два одинаковых в одном отображении — `upstream_invalid`.
- Многострочный текст (`TextNode`) — только `description`, `text` и `content` в записи, взятой целиком; в записи
  списка это строка.
- Время — момент ISO 8601 в UTC. Длительность — `PT…H…M` из минут: `P1D` сервера — рабочий день инстанса. Подвыборка
  под длительностью — `bad_usage`.
- `url`, `thumbnailURL`, `avatarUrl` и `iconUrl` сервер присылает путём; модуль делает их абсолютными от адреса клиента,
  без пароля. Не путь — `upstream_invalid`. Запрос `base64Content` (самого файла) — `bad_usage`.
- Кастом-поля, названные в выражении, идут в порядке называния, все поля задачи — по `ordinal`. Поля, которого у
  задачи нет, в документе нет.
- Связи — отображение фразы связи на задачи. Пустые слоты опускаются, `null` среди слотов — `upstream_invalid`.
- Комментарии запрашиваются выбором `Comments`; удалённые выбрасываются, порядок — по `created`.
- Запись отвечает документом записанного. Расхождение с отправленным — `upstream_invalid` с `mismatch`, где `actual` —
  присланное дословно.

## Активности

- `added` и `removed` — всегда список. Схемы под ними — `ActivityItem` и `BundleElement`; имя вне них — `unknown_name`
  до запроса.
- `category` — id категории YouTrack. `field` — имя поля в проекте или непереведённая фраза связи: переведённую метку
  модуль сводит к фразе по `/api/issueLinkTypes`. Вложенное имя под `category` и `field` — `bad_usage`.
- Без категорий в запросе уходят все. Незнакомая категория — `unknown_name` до запроса: сервер на неё молча отвечает
  `[]`, а на запрос без категорий — `400`.

## Отвергнуто

- Тела с тремя состояниями по всей спецификации.
- Отсутствующий ключ — всегда ошибка или всегда пропуск.
- Набор схем по присланным типам; подтипы в overlay.
