# Транспорт отправляет один раз, а ошибка — тип, который называет, что делать дальше

Неверная догадка о повторе запроса даёт двойную запись или бесконечный цикл, а одна ошибка на всё не даёт вызывающему
решить, повторять ли. Здесь решено, как модуль отправляет запросы и какими ошибками отвечает.

## Решение

- **Свой `http.Transport` ничего не отправляет дважды:** keep-alive выключен, редиректы не выполняются, протокол
  только HTTP/1.1, прокси-переменные не читаются. net/http молча повторяет запрос по HTTP/2 на `GOAWAY` и по
  сломавшемуся переиспользованному соединению — оба пути закрыты. Таймауты: соединение 10 с, TLS 10 с, заголовки ответа
  60 с.
- **Модуль не повторяет ни запись, ни чтение.** Решает вызывающий по типу ошибки.
- **Граница «запрос ушёл» — `httptrace.WroteRequest`.** `Send` отправляет запись и ставит `TransportError.Written`,
  если байты запроса ушли до сбоя: такая запись могла пройти. Оборванное тело ответа под 2xx и 5xx — тоже `Written`,
  под остальными статусами сервер запись отверг. Чтения этой границы не знают: `Written` у них нет.
- **Каждый класс исхода — свой тип, и все достаются `errors.As`:**

  | Тип | Когда |
  |---|---|
  | `*ArgumentError` | аргумент нельзя отправить как написан; сеть не тронута |
  | `*TransportError` | ответа нет; `Written` — запись могла пройти |
  | `*StatusError` | статус не 200; `Code` и `Description` — `error` и `error_description` YouTrack, `Body` — тело дословно |
  | `*ResponseError` | ответ не сходится с запросом; `Write` — запись прошла под 200 |
  | `*MismatchError` | запись прошла, поле вернулось не тем, что записано |
  | `*FieldNameError`, `*ValueError`, `*RequiredFieldError` | запись отвергнута до отправки по метаданным проекта |
  | `*PermissionError` | проект ответил без единого поля |
  | `*ChangedFieldError` | поле сменилось между двумя чтениями |

- **Слова сервера передаются дословно.** `StatusError` несёт `Code`, `Description` и `Body`; прозу ошибки модуля
  вызывающий не разбирает.
- **5xx на запись от YouTrack — отказ YouTrack, иначе ответил промежуточный узел, и исход неизвестен.** YouTrack
  отвечает JSON-объектом со строковым `error`; `StatusError.Uncertain()` — запись, 5xx и `Code` пустой. Запись,
  принятая под 2xx, которое модуль не читает, — `Accepted()`.
- **Статусу без тела нужной формы модуль не верит.** Не-JSON под статусом, который не 5xx, — `ResponseError`: по
  адресу с лишним путём перед `api/` сервер отвечает `200` и HTML-страницей веб-клиента. Под 5xx тело бывает любым.
- **`Request` в ошибке — отправленный запрос, пригодный для повторной отправки.** Пароль в userinfo маскируется, в
  query раскрыты только `,` `(` `)` `$`.
- **Адрес и токен проверяются в `New`:** абсолютный `http`- или `https`-URL с хостом, без query и фрагмента; токен
  непустой и без управляющих символов, кроме TAB, иначе заголовок не собрать.

## Соответствие кодам ytrack

| Ошибка модуля | Код ytrack |
|---|---|
| `ArgumentError`, `ValueError` | `bad_usage` |
| `FieldNameError` | `unknown_name` |
| `RequiredFieldError` | `missing_required` |
| `StatusError` 400 | `rejected` |
| `StatusError` 401, 403; `PermissionError` | `denied` |
| `StatusError` 404 | `not_found` |
| `StatusError` 5xx от YouTrack и статус вне таблицы; `TransportError` без `Written`; `ChangedFieldError` | `upstream_failed` |
| `ResponseError`, `MismatchError` | `upstream_invalid` (после записи — код возврата 2) |
| `TransportError.Written`; `StatusError.Uncertain()` | `write_uncertain` |

## Отвергнуто

- **Одна ошибка с полем «код».** Словарь кодов принадлежит CLI ([ADR-0001](0001-the-module-returns-go-values-and-the-cli-keeps-the-document.md)),
  а Go-потребителю нужны поля, а не строка.
- **Ограничитель частоты и повтор на 5xx.** Запросы идут по одному, а повтор — решение вызывающего.
- **Чтение обратно при неизвестном исходе записи.** Создание так не проверить, и решать должен тот, кто писал.
