# Тип поля — строка таблицы, класс берётся с задачи, запись сверяется по ключу значения

Факты — YouTrack 2026.1.13757.

- Тип кастом-поля — пара `valueType` и `isMultiValue`. Таблица типов выписана руками, строка на пару: класс поля в теле
  записи, ключ значения и есть ли бандл. Пара вне двадцати строк — `upstream_invalid`, `FieldType.Known() == false`.

  | valueType | ключ значения | запись |
  |---|---|---|
  | enum, state, version, build, ownedField, group | `name` | `{"name": …}` |
  | user | `login` | `{"login": …}` |
  | period | `PT1H30M` из `minutes` | `{"minutes": N}` |
  | date | день ISO 8601 | полдень UTC этого дня, мс |
  | date and time | момент ISO 8601 в UTC | мс |
  | integer, float, string | сам скаляр | скаляр |
  | text | `text` | `{"text": …}` |

- `$type` поля в теле записи берётся с задачи, если поле на ней стоит (под воркфлоу это
  `StateMachineIssueCustomField`), иначе из таблицы. Поэтому обновление сначала читает задачу, а создание — проект.
- Имя поля разрешает модуль: по `name`, затем по `localizedName`, без учёта регистра. В тело уходит канонический
  `name`: на другое имя сервер отвечает `500`. Имя без поля — `unknown`, имя нескольких полей — `ambiguous` с
  `candidates`.
- Имя значения (элемент бандла, логин) разрешает сервер и правит в нём регистр, поэтому ответ сверяется с записанным
  без учёта регистра. Многозначное поле пишется целиком и сверяется как набор: сервер возвращает его в своём порядке.
- Опустошение пишет `null` в однозначное поле и `[]` в многозначное.
- До записи отвергается всё, что сервер сохранил бы иначе: пустое значение, пробелы по краям и NEL, LS, PS в строке,
  период не `PT…H…M` или длиннее `2^31−1` минут, день не `ГГГГ-ММ-ДД`, момент без смещения или точнее миллисекунды,
  целое вне int32, число не по грамматике JSON. Все негодные значения называются одной ошибкой.
- Создание требует все обязательные поля, кроме тех, что проект заполняет сам, и скрытых условием. Обновление
  проверяет только поля, которые опустошает.
- Поле, скрытое условием, отвергается только при создании: тогда сервер молча его выбрасывает, а при обновлении
  отвечает `400` сам. Видимость по условию считается по значениям той же записи, как у сервера.
- Пользователь пишется только логином: на `me` и на пользователя вне `aggregatedUsers` сервер отвечает `400`.
- Ответ на запись сверяется с записанным; расхождение — `upstream_invalid` с `mismatch` и `AfterWrite`. `WriteFields`
  идёт тем же путём, что `Create` и `Update`.
- Поля задачи упорядочены по `ordinal` привязки, при равенстве — по номеру привязки: у полей, привязанных через REST,
  `ordinal` у всех 0. Поля проекта — по `ordinal`.
- Бандл — `values` у enum, state, version, build и ownedField. `Fields.Bundle` поля без бандла — `bad_usage`.
- Пустой список полей у `Fields` — `denied` с `project` и `permission`: токену без
  `jetbrains.jetpass.project-read` сервер отвечает `200` и `[]`. Запись пустой список отказом не считает.

## Запись времени

- Длительность пишется только как `{"minutes": N}`: с одним `id` сервер отвечает `400`. Отрицательная длительность и
  длительность не из целых минут отвергаются до записи; ноль оставлен серверу.
- Запись без дня уходит без `date`, и сервер ставит свой сегодняшний день. День пишется полднем UTC, а читается
  полуночью UTC, в которой хранится.
- Обновление несёт только названные части; `null` в `type`, `text` и `value` атрибута их опустошает.
- Тип работы берётся из набора проекта `plugins.timeTrackingSettings.workItemTypes` и уходит по `id`; имя не из набора —
  `unknown_name`.

## Что сервер хранит иначе

- Хранятся байт в байт и уходят как есть: заголовок задачи с пробелами и TAB по краям; описание с хвостовыми пробелами,
  строками `---`, `~~~` и символом вне BMP; текст комментария, содержимое статьи и текст записи времени с CR, NEL,
  U+2028 и BOM; заголовок статьи с TAB.
- В заголовке задачи сервер заменяет LF, CR, NEL, U+2028 и U+2029 — такой заголовок отвергается.
- С краёв имени тега сервер срезает `\t\n\v\f\r`, U+001C–U+001F, Zs, Zl и Zp — такое имя отвергается; LF внутри имени
  сервер хранит.
- В имени файла вложения отвергаются `\` и `"` (сервер хранит только часть после обратной черты), CR и LF (сервер
  хранит `%0D` и `%0A`) и символы до U+0020 по краям (сервер их срезает). Подписанный `url` вложения живёт до трёх дней.
- Логин с `/` уходит экранированным; `""`, `.` и `..` отвергаются.
- Связь задачи с самой собой сервер отвечает `200` и не пишет — модуль её отвергает.
- Запись во взятый назад комментарий сервер принимает молча — модуль её отвергает. Пустой комментарий сервер у задачи
  отвергает, а у статьи хранит — модуль не пишет ни тот, ни другой.

## Кэш метаданных

- Кэш читают `Fields.Metadata`, `Fields.Show` и `Fields.Bundle`; пишут `Fields.ReadMetadata` и они же при промахе.
  Запись берёт метаданные с сервера.
- Кэш не бывает причиной ошибки: любое расхождение с сервером (имя, форма id, тип вне таблицы, `404`, ответ другой
  формы, поле сменилось) — промах, после которого проект читается заново. `denied`, `rejected`, сбой сети и `5xx` —
  не промах.
- `Bundle.Field.CanBeEmpty` берётся из ответа о самом поле.
- Каталог кэша — на пару адреса и токена, `0700`, файлы `0600`, токена в них нет. Кэш пишется сразу после ответа; кэш,
  который не читается или не пишется, просто не используется.

## Отвергнуто

- Класс поля только из таблицы: поле под воркфлоу сервер держит другим классом.
- Кэш в памяти.
- Повтор чтения на сменившемся поле.
