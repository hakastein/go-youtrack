# Тип поля — строка таблицы, класс копируется с задачи, запись проверяется по ключу значения

Сервер присылает только поля из `fields=`, у даты, числа и строки один `$type` значения, а класс тела записи зависит от
типа и кратности поля нерегулярно. Здесь решено, как модуль узнаёт тип поля, что считает его значением и как проверяет
запись. Факты измерены на YouTrack 2026.1.13757 — дев-инстансе ytrack.

## Решение

- **Тип поля — пара `fieldType.valueType` и `fieldType.isMultiValue`.** Таблица выписана вручную, по строке на пару,
  потому что она нерегулярна: строка задаёт класс тела записи, ключ значения и есть ли бандл. Пара вне двадцати строк —
  тип, которого модуль не знает: чтение и запись такого поля — `upstream_invalid`, `Fields.Metadata` отдаёт его с
  `Known() == false`.
- **Ключ значения зависит от типа:**

  | valueType | ключ значения | как пишется |
  |---|---|---|
  | enum, state, version, build, ownedField, group | `name` | `{"name": …}` |
  | user | `login` | `{"login": …}` |
  | period | ISO 8601 из `minutes`: `PT1H30M` | `{"minutes": N}` |
  | date | день ISO 8601 в UTC | полдень UTC этого дня в миллисекундах |
  | date and time | момент ISO 8601 в UTC | миллисекунды |
  | integer, float, string | сам скаляр | скаляр |
  | text | `text` | `{"text": …}` |

  `Value.ID` несут значения бандла, пользователи и группы; у `PeriodValue` и `TextFieldValue` `id` — не идентификатор.
  `Value.LocalizedName` — `localizedName` значения бандла: `State` хранит `In Progress` и показывает «В работе».
- **Кодирование и чтение значения по типу экспортированы:** `FieldType.Encode` даёт тело записи и ключ, `ReadValue`
  читает один элемент значения как его присылает сервер, `Named` и `Same` — правило сравнения, `BundleFields` —
  выражение бандла, `ValueKeys` — члены, по которым значения именуются. Потребитель, который собирает запросы сам,
  берёт знание здесь и не держит своей таблицы.
- **Класс `$type` в теле записи копируется, а не вычисляется.** Поле, которое стоит на задаче, пишется классом,
  который назвал сервер (`StateMachineIssueCustomField` у поля под воркфлоу), поле, которого на задаче нет, — классом из
  таблицы. Поэтому обновление читает задачу с `customFields($type,name,projectCustomField(id))` и метаданными проекта
  одним `GET` до `POST`, а создание — проект.
- **Имена полей модуль разрешает сам:** по `name`, затем по `localizedName`, без учёта регистра. В тело уходит
  канонический `name`, потому что на другое имя сервер отвечает `500`. Имя без поля — `unknown_name` с
  `unknown: [{field, nearest}]`, имя нескольких полей — с `ambiguous` и `candidates`.
- **Имена значений разрешает сервер.** Он исправляет регистр (`новая` — `Новая`, `ADMIN` — `admin`), поэтому проверка
  записи именованных значений регистр не учитывает. Имя не из бандла и логин вне поля сервер отвергает `400`.
- **Многозначное поле пишется целиком.** Сервер заменяет весь набор и возвращает его в своём порядке, поэтому
  проверка записи сравнивает набор. Значения одного поля из нескольких `FieldWrite` складываются.
- **Опустошение (`Clear`) пишет `null` в однозначное поле и `[]` в многозначное.** Опустошение обязательного поля
  (`canBeEmpty: false`) — `missing_required` до запроса; поле и значение и `Clear` разом — `bad_usage` под `invalid`.
- **До запроса отвергается всё, что сервер, по измерениям, сохранит иначе:** пустое значение, пробелы по краям и
  NEL, LS, PS в строке (сервер режет и заменяет), период не в `PT…H…M` или длиннее 2³¹−1 минут, день не `ГГГГ-ММ-ДД`,
  момент без смещения или точнее миллисекунды, целое вне int32, число не по грамматике JSON. Все негодные значения
  называются одной ошибкой.
- **Обязательные поля проверяются до запроса при создании, и `missing_required` называет их все.** Поле, которое
  проект заполняет сам, и поле, скрытое условием, не требуются. Обновление проверяет только поля, которые опустошает.
- **Поле, скрытое условием, отвергается только при создании**, потому что тогда сервер молча его отбрасывает. При
  обновлении такую запись сервер отвергает сам, `400`. Условие сервер вычисляет по значениям той же записи, поэтому и
  модуль вычисляет его по телу.
- **Пользователь пишется только логином.** `me` сервер не читает как вызывающего, а пользователя вне
  `aggregatedUsers` отвергает `400`.
- **Дата пишется полднем UTC**, потому что он приходится на один день во всех поясах от UTC−12 до UTC+11:59, а сервер
  относит момент ко дню в поясе автора. Проверка записи сравнивает день.
- **Запись отвечает задачей, как её держит сервер,** потому что воркфлоу может поменять другое поле, а расхождение
  записанного с ответом — `upstream_invalid` с `mismatch` и `AfterWrite` под `200`. `WriteFields` идёт тем же путём,
  что `Issues.Create` и `Issues.Update`, и отличается только ответом: `*Issue` вместо документа.
- **Значения на задаче упорядочены по `ordinal` привязки, при равенстве — по номеру привязки как числу,** потому что
  сервер отдаёт их в порядке `id`, а у полей, привязанных через REST, `ordinal` одинаковый — `0`. Поля проекта
  (`Fields`) — по `ordinal`, при равенстве в порядке ответа.
- **Бандл — `values` у enum, state, version, build и ownedField** (`FieldType.HasBundle`); у user `aggregatedUsers` —
  не бандл значений, у остальных типов источника нет. `Fields.Bundle` у поля без бандла — `bad_usage`, и только после
  того, как тип поля подтверждён сервером.
- **Пустой список полей проекта у `Fields` — `denied` с `project` и `permission`,** потому что токену без права
  `jetbrains.jetpass.project-read` сервер отвечает `200` и пустым списком, а не `403`. Запись пустой список отказом не
  считает: проект без кастом-полей принимает заголовок и описание.

## Запись времени

- **Длительность пишется только как `{"minutes": N}`,** потому что длительность с одним `id` сервер отвергает `400`.
  Отрицательная и не из целых минут отвергается до запроса, ноль проверяет сервер.
- **Запись без дня уходит без `date`**, и сервер пишет её на свой сегодняшний день. День пишется полднем UTC и
  печатается полуночью UTC, в которой хранится; на вход принимается календарный день или та же полночь.
- **Обновление несёт только названные части:** остальные сервер не трогает, а `null` в `type`, `text` и в `value`
  атрибута их опустошает. Текст сервер хранит байт в байт, с CR и пробелами по краям.
- **Допустимые типы работ — набор проекта `plugins.timeTrackingSettings.workItemTypes`**, который модуль читает с
  задачи. Имя не из набора — `unknown_name` до записи. Тип отправляется только по `id`.

## Кэш метаданных

- **Кэш читают `Fields.Metadata`, `Fields.Show` и `Fields.Bundle`, пишут `Fields.ReadMetadata` и они же при промахе.**
  Запись читает метаданные с сервера вместе с задачей или проектом, с условиями и значениями по умолчанию, и кэш не
  трогает.
- **Кэш подтверждает, но не отказывает.** `Fields.Metadata` отдаёт кэш с `FromCache`, и вызывающий, у которого кэш
  разошёлся с сервером, читает снова `Fields.ReadMetadata`. `Fields.Show` и `Fields.Bundle` делают это сами, одним
  путём: по кэшу берётся id поля, затем поле читается с
  сервера и его имя, перевод и тип сверяются с кэшем. Всякое расхождение — промах: имя не нашлось, id не сходится с
  формой, тип не из таблицы, `404`, ответ другой формы, поле сменилось. После промаха проект читается заново.
  `denied`, `rejected`, сбой сети и 5xx промахом не считаются. Без кэша то же расхождение между двумя чтениями —
  `upstream_failed` с `project` и `field`.
- **`Bundle.Field.CanBeEmpty` берётся из ответа о поле,** потому что сверка по имени и типу его не покрывает; в кэше
  `canBeEmpty` лежит для `Fields.Metadata`, и там он стар настолько же, насколько остальной кэш.
- **Каталог принадлежит паре адреса и токена,** потому что права фильтруют и поля, и значения. Каталоги `0700`, файлы
  `0600`, токена в файлах нет, файл — на проект. Кэш пишется сразу после ответа, чтобы вызов, кончившийся ошибкой,
  оставлял его тёплым. Кэш, который не читается или не пишется, — просто нет кэша.

## Отвергнуто

- **Класс из таблицы всегда.** Поле под воркфлоу сервер держит другим классом.
- **Значение в форме типа Go.** Двадцать типов дали бы двадцать ветвей у каждого потребителя; ключ значения текстом —
  то, что печатает документ, пишет TMS и читает kraken.
- **Кэш в памяти.** Долгоживущему процессу два запроса на бандл не в тягость, а устаревшие метаданные — да.
- **Повтор чтения на сменившемся поле.** Повтор — решение вызывающего ([ADR-0002](0002-the-transport-sends-once-and-an-error-carries-a-code.md)).
