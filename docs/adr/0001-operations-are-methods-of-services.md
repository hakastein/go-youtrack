# Операции — методы сервисов, ответ — документ или значение Go

Одни вызывающие берут ответ под своим выражением полей и печатают его как есть, другие работают со значениями в коде.
Модуль отдаёт оба вида одним клиентом и одной формой вызова, по сервису на сущность, как принято в Go SDK.

- Вызов: `c.<Сервис>.<Действие>(ctx, id сущности…, вход записи, opts)`. Контекст первым — ради отмены и таймаута;
  опции указателем на структуру — `nil` значит умолчания, а новая опция не ломает сигнатуру.
- Вход записи — указатель на структуру (`*IssueInput`, `*IssueUpdate`). Значением его берут только `Tags.Create`
  (`TagSharing`), `Attachments.Create` (`File`) и `Users.Find` (`limit int`).
- `opts.Fields` — выражение полей ответа: пусто — поля по умолчанию операции, `+x` — они и `x`.
- Обновлению нужны три состояния части: не трогать, записать, опустошить. Поэтому поле `nil` оставляет часть как есть,
  значение пишет её, `ClearX` опустошает.
- `Show`, `List`, `Children`, `Create`, `Update`, `Delete`, `Add`, `Remove` отвечают документом `*Node` — ключи в
  порядке выражения вызывающего. `Issues.Get`, `Issues.WriteFields`, `Fields.Metadata`, `Fields.ReadMetadata`,
  `Fields.Bundle`, `Users.Me`, `Users.Find` отвечают значением Go.
- `Node` — модель документа, а не формат: все решения о данных принимаются при построении узла, поэтому любая печать
  (YAML, JSON) выводит одно и то же.
- Вход — структуры, а не строки флагов: грамматика строк у каждого вызывающего своя. Проза ошибок говорит словами
  предметной области.
- Пакеты: корневой, `ytapi` (из модуля его зовёт только `ytapi.go`) и `fake` (модуль он не импортирует).

## Отвергнуто

- Конструктор операции, отдающий замыкание над клиентом: проверка вызова и сам вызов разнесены, API неидиоматичен.
- Формат вывода в модуле: печать у каждого вызывающего своя.
- Значение кастом-поля объединением типов Go: двадцать ветвей у каждого вызывающего.
