# Тесты — контракт через экспорт против фейкового сервера

Тест должен падать, только когда ломается поведение модуля, — не когда меняется версия YouTrack, формулировка ошибки
или устройство кода.

- Тесты — в пакете `youtrack_test`, на testify и таблицах, через экспорт; тестовых швов в проде нет.
- Кассет и тестов против живого YouTrack нет: они краснеют со сменой версии сервера, когда модуль ничего не нарушил.
  Факт сервера, на котором стоит решение, записывается в ADR с версией.
- Отказ до сети проверяется против `fake.ServeNothing`, который роняет тест на любом запросе; поведение по ответу —
  против `fake.Serve`.
- Ассерт стоит на значении: на документе целиком, на значении Go, на `Error` с кодом и деталями. Прозу проверяет
  только `NotEmpty`: правка формулировки поведения не меняет.
- Полный запрос (`fields=`, тело) сверяет только тест про этот запрос, чтобы правка полей по умолчанию роняла только
  его.
- Каждую гарантию ADR держит тест, который падает на мутации, снимающей её. Таблица отказов сверяет, каким правилом
  отвергнут кейс: кейс, отвергнутый не тем правилом, иначе оставался бы зелёным. В теле теста нет логики.
- Фикстуры названы по проверяемому свойству (`First`, `Second`, `Third`), а не взяты с инстанса.
- Чужой код (net/http, `encoding/json`, сгенерированный клиент) и сам YouTrack не тестируются.

## Фейковый сервер

- `fake` публичный: тестам кода поверх модуля нужен тот же сервер.
- Сервер один на тестовый пакет, каждый тест получает свой префикс пути: на WSL каждый `bind()` стоит до секунды.
- Журнал отдаёт запрос по номеру через `require`, чтобы пропущенный запрос был провалом, а не паникой. Адрес, где никто
  не слушает, — `NobodyListens`, порт 1.
- Отдельный сервер поднимает только тест, которому нужно перестать слушать между запросами (`ServeAlone`) или
  прочитать тело самому (`ServeUnread`).
- Ответы даёт тест. Исключение — сборщики разметки поиска `Searching`, `Markup` и `StyleRange`: разметку ждёт каждый
  поиск задач с предупреждением.
